# Log Levels

Traces can have a lot of observations ([data model](/docs/tracing#introduction-to-traces-in-langfuse)). You can differentiate the importance of observations with the `level` attribute to control the verbosity of your traces and highlight errors and warnings. Available `levels`: `DEBUG`, `DEFAULT`, `WARNING`, `ERROR`.

In addition to the level, you can also include a `statusMessage` to provide additional context.

  ![Trace log level and statusMessage](/images/docs/trace-log-level.png)

**Python SDK**

When using the [`@observe()` decorator](/docs/sdk/python/decorators):

```python
from langfuse import observe, get_client

@observe()
def my_function():
    langfuse = get_client()

    # ... processing logic ...
    # Update the current observation with a warning level
    langfuse.update_current_span(
        level="WARNING",
        status_message="This is a warning"
    )
```

When creating [observations](/docs/observability/data-model#observations-traces-and-sessions) directly:

```python
from langfuse import get_client

langfuse = get_client()

# Using context managers (recommended)
with langfuse.start_as_current_observation(as_type="span", name="my-operation") as span:
    # Set level and status message on creation
    with span.start_as_current_observation(
        name="potentially-risky-operation",
        level="WARNING",
        status_message="Operation may fail"
    ) as risky_span:
        # ... do work ...

        # Or update level and status message later
        risky_span.update(
            level="ERROR",
            status_message="Operation failed with unexpected input"
        )

# You can also update the currently active observation without a direct reference
with langfuse.start_as_current_observation(as_type="span", name="another-operation"):
    # ... some processing ...
    langfuse.update_current_span(
        level="DEBUG",
        status_message="Processing intermediate results"
    )
```

Levels can also be set when creating generations:

```python
langfuse = get_client()

with langfuse.start_as_current_observation(
    as_type="generation",
    name="llm-call",
    model="gpt-4o",
    level="DEFAULT"  # Default level
) as generation:
    # ... make LLM call ...

    if error_detected:
        generation.update(
            level="ERROR",
            status_message="Model returned malformed output"
        )
```

**JS/TS SDK**

When using the context manager:

```ts
import { startActiveObservation, startObservation } from "@langfuse/tracing";

await startActiveObservation("context-manager", async (span) => {
  span.update({
    input: { query: "What is the capital of France?" },
  });

  updateActiveObservation({
    level: "WARNING",
    statusMessage: "This is a warning",
  });
});
```

When using the `observe` wrapper:

```ts
import { observe, updateActiveObservation } from "@langfuse/tracing";

// An existing function
async function fetchData(source: string) {
  updateActiveObservation({
    level: "WARNING",
    statusMessage: "This is a warning",
  });

  // ... logic to fetch data
  return { data: `some data from ${source}` };
}

// Wrap the function to trace it
const tracedFetchData = observe(fetchData, {
  name: "observe-wrapper",
});

const result = await tracedFetchData("API");
```

When creating observations manually:

```ts
import { startObservation } from "@langfuse/tracing";

const span = startObservation("manual-observation", {
  input: { query: "What is the capital of France?" },
});

span.update({
  level: "WARNING",
  statusMessage: "This is a warning",
});

span.update({ output: "Paris" }).end();
```

See [JS/TS SDK docs](/docs/sdk/typescript/guide) for more details.

**OpenAI SDK**

When using the [OpenAI SDK Integration](/integrations/model-providers/openai-py), `level` and `statusMessage` are automatically set based on the OpenAI API response. See [example](/integrations/model-providers/openai-py).

**Langchain**

When using the [LangChain Integration](/integrations/frameworks/langchain), `level` and `statusMessage` are automatically set for each step in the LangChain pipeline.

## How levels are stored and mapped [#level-mapping]

`level` is stored and returned as one of the four strings `DEBUG`, `DEFAULT`, `WARNING`, `ERROR`. There is no numeric encoding: the Observations API, exports, and filters all use these exact strings, and `level` is one of the fixed filter parameters of the [Observations API](/docs/api-and-data-platform/features/public-api#observations-filters). Observations ingested without a level are stored as `DEFAULT`.

When you send spans through the [OpenTelemetry endpoint](/integrations/native/opentelemetry), Langfuse derives the level in this order:

1. The `langfuse.observation.level` span attribute, if present. Matching is case-insensitive and accepts common aliases: `TRACE` and `VERBOSE` map to `DEBUG`; `INFO`, `LOG`, `NOTICE`, `OK`, and `SUCCESS` map to `DEFAULT`; `WARN` maps to `WARNING`; `FATAL` and `CRITICAL` map to `ERROR`. Unknown values are ignored and fall through to the next rule.
2. Otherwise, a span whose OpenTelemetry status code is `ERROR` becomes `ERROR`.
3. Otherwise, `DEFAULT`.

`statusMessage` is taken from the `langfuse.observation.status_message` attribute, falling back to the span's OpenTelemetry status message. OpenTelemetry log-record severity fields (`SeverityNumber`, `SeverityText`) are not read; set the span attribute when you need a level other than `DEFAULT` or `ERROR`.

## Filter Trace by Log Level

When viewing a single trace, you can filter the observations by log level.

_[Video: Show and hide DEBUG observations](https://static.langfuse.com/docs-videos/250210-trace-log-level-filter.mp4): Trace detail of a LangGraph trace. The tree notes “5 hidden observations below DEFAULT level”; click “Show all” to reveal the DEBUG spans. Open the tree's “⋯” menu > “Min Level” and choose DEFAULT to hide them again._
