# Tracing

Tracing records what your agent does (LLM calls, tool use, and control flow) so you can debug individual runs and understand behavior over time. Laminar also [extracts the task from every agent run](https://laminar.sh/docs/tracing/task-extraction.md), so the traces table lists what each run was asked to do and SQL can group runs by it. It also [versions each agent](https://laminar.sh/docs/tracing/agent-versions.md) as its system prompt and tools change, and tags every trace with the version and release that produced it.

Tracing is also the entry point into Laminar: it’s how production runs become data in the platform. Once you’re tracing, you can read each run as a transcript in the [trace view](https://laminar.sh/docs/platform/viewing-traces.md), define [Signals](https://laminar.sh/docs/signals) to extract outcomes and failures across traces, and replay runs in the [Debugger](https://laminar.sh/docs/debugger/introduction.md) to reproduce and fix what went wrong. From there, turn real failures into [Datasets](https://laminar.sh/docs/datasets) and run comprehensive [Evaluations](https://laminar.sh/docs/evaluations).
